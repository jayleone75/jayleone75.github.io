What it does

Turns public purchase records into account strategy.

Any vendor or reseller selling infrastructure into a state agency wants to know three things: what does this department already own, when does it come up for renewal, and who currently sells to them. None of those can be answered from the raw files. Two incompatible export formats ship under the same file extension. There is no product taxonomy. Contract terms live in free-text line descriptions. The same supplier is spelled three different ways in one file.

The platform ingests those exports, reconciles them into one schema with full provenance, classifies every purchase into a product taxonomy, overlays contract-renewal timing and statewide reseller authorizations, and generates client-ready department briefs. It is not built for one territory or one manufacturer. Every state, county, and large municipality publishes procurement data with the same characteristics, and the taxonomy, lifecycle overlay, and brief generation all generalize.

Engineering judgment

Five things that were not what they looked like.

It looked like — one export format

Two schemas, one file extension

The state ships two formats: one row per purchase order, and one row per line item. Nothing in the filename distinguishes them. Treating them alike counted 75,196 spreadsheet rows as 24,171 purchase orders and repeated each order's total across every one of its lines.

Cost of the surface reading: one department's spend overstated by $105.6M. Fixed by detecting format from column signature and normalizing both into a two-table schema, with a standing rule that order totals are never summed across line items.
It looked like — a contract date

A delivery date wearing a term's clothes

62% of dated purchase orders record a delivery date where the contract term should be. The real term is written into the description as free text. An extractor now parses those terms, gated on a corroboration rule: a date is written to the database only if it appears literally in the state's own text. 968 of 968 passed on the first production run.

Recovered $55.7M of renewal signal that no query could previously see. On Transportation alone it tripled the count of agreements expiring within twelve months, from 39 to 119.
It looked like — a job for a model

The classification already in the data

Product classification runs as a four-stage cascade in deliberate order: keyword rules on the order title, then the state's own UNSPSC product codes, then keyword rules on line-item text, and only then a model for the residue. UNSPSC was already sitting in the source files, unused.

11,261 records resolved at zero marginal cost. Unclassified purchases fell from 18.6% to 7.0%, and 91% of orders never reach a paid inference stage. Finding the code that was already there was worth more than any prompt engineering.
It looked like — an improvement

An enrichment that read better and was worse

A model pass was run over product descriptions to make them cleaner and more consistent. It produced text that looked considerably better on inspection. Measuring it told a different story: 7,575 enriched rows carried only 681 distinct texts, and 74% of rows had dropped a model number or SKU that was present in the original.

Rejected the approach, salvaged the one component that worked, and wrote up the negative result so it would not be attempted again. This is the decision the whole project turns on.
It looked like — a clean refresh

A re-import that quietly ate human judgment

Re-importing a department deletes and rebuilds its rows. Hand corrections lived on those rows, so they went with them, silently and without error. Discovered only after 13 corrections were already gone.

Corrections now live in a separate ledger keyed by composite identity, so provenance survives destructive operations. Human judgment is the most expensive data in the system and it was the least protected.
Architecture

Where the model is, and where it isn't.

Deterministic code

  • Ingest and format detection
  • Normalization, supplier reconciliation
  • Joins, ranking, aggregation
  • Classification stages 1–3
  • Contract award matching
  • Every reported figure

Model

  • Narrative positioning in briefs
  • Conversational query interface
  • Classification residue (<9%)
  • Term parsing, corroboration-gated
The rule, enforced not aspirational The pipeline runs end to end with zero model calls. The brief generator makes exactly two, and neither one produces a number.

Grounding is verified

Every figure in a generated client narrative was extracted and traced back to its source query. All seven matched. An instruction to use only the supplied numbers is a hypothesis until someone tests it.

Cost as a design constraint

Prompt caching across tool-loop rounds, model tiering by task, rules before inference. A complete client brief costs about $0.03 to generate.

Inference never reads as fact

Renewal signals appear in three visually distinct tiers. Confirmed carries a dated term. Publicized carries a vendor bulletin and a source URL. Inferred produces a question, never a date, because the person using it has to defend it in a client meeting.

Stack

Python · pandas · SQLite · Flask · Anthropic API with tool use, streaming, prompt caching, and server-side search

Scope

~9,400 lines · 12 Python modules · Flask app with nine functional areas · ingest, normalization, classification, contract loading, term extraction, export generation

Honest limits

Single-tenant SQLite. No authentication. No tests beyond route smoke checks. One operator. That is the right shape for this stage; building for multi-tenancy before there are paying clients would have been the worse call.
